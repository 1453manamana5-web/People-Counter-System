# Luxnora Ver.5.3 会話文脈と学習モデル接続の検証

基準開発ブランチは `luxnora/v5-2-curriculum` の `1d008ff`。調査時のmainは `ebb658b`。既存の管理アプリ、機能レジストリ、Core、Planner、承認経路を使った。管理パネルの会話状態と読み取り計画は開発ブランチに実装し、学習モデルは隔離実行とシャドー評価で接続した。本番配備は未実施。 [Ver.5.2の報告](luxnora-v5-2-learning.md)

## 会話と実行

会話状態は開催区分と管理者のパネルに紐付く。比較、集計、端末、記録、診断を目的別に保持し、現在の対象、前の条件、結果が得られたかどうか、失効時刻を記録する。保持時間は5分。時間帯を変更しても比較指標や別の端末の対象は維持する。修正対象が曖昧なら対象を確認し、取り消しで状態を消す。会話の状態には実データの値や操作の承認を保存しない。開催区分・閲覧状態が処理中に変わった場合は結果を破棄する。取得済みの事実は次の要求で現状から検証する。 [文脈管理](../management-app/src/luxnora/context.ts) · [Core](../management-app/src/luxnora/core.ts)

比較、台帳、端末観測の既存入力関係の上に、登録済みの案内を読み取り計画へ追加した。複数の依頼を解釈できた場合は、各構成要素を個別に検証して最大4目標まで実行する。前年を取得できない場合も独立した端末の確認を続け、前年の値を必要とする条件付き調査は保留する。台帳検算や端末報告の既存の鮮度チェックはPlanner側を使う。案内の結果は画面遷移や操作を起こさない。汎用の依存関係探索や、因果関係の自動推定は未実装。 [Planner](../management-app/src/luxnora/planner.ts) · [機能レジストリ](../management-app/src/luxnora/capabilities.ts)

## データと学習

| 区分 | 合成会話 | 利用者の発話ターン | 異なる発話 | 最終発話の種類 |
| --- | ---: | ---: | ---: | ---: |
| 学習 | 1,000 | 3,666 | 145 | 10 |
| 検証 | 200 | 732 | 58 | 9 |
| 独立評価 | 300 | 1,400 | 68 | 9 |

各ケースは実際の発話列をCoreへ順に渡す。話題の切り替え、訂正後の再参照、曖昧な複数要求、取り消し、11ターンの履歴などを含む。発話と構造の分割は別に記述し、同一の会話列を分割間で再利用していない。構造の種類と発話の種は限られ、同じ発話を別の文脈で使用している。人が独立に収集した会話や実利用者データは含まない。単一・複合依頼10,000件の新規学習は、今回の品質で用意できなかったため未実施。Ver.5.2の単一依頼モデルの95%目標をこの評価から判定することはできない。 [データ品質と圧縮データ](../research/luxnora-v53/data)

モデルの出力は5話題または確認（保留）の6クラス。操作、時刻、権限、実行コードを出力しない。文字n-gramのMLP、直近3発話、解析済み話題の要約、構造化済み文脈、GRU系列、Ruri＋MLP、正解文脈付き比較をCPUで実学習した。Ruri v3 30Mの既存量子化済み重みは凍結し、48ユニットの専用ヘッドのみ学習した。学習を3初期値で繰り返した。

| --- | ---: |
| 現発話のみ | 81〜92 |
| 生の直近3発話 | 160〜164 |
| 解析済み話題の要約 | 216〜218 |

Ver.5.2の35.5%は別形式の評価のため、上表との直接比較に使っていない。初回のRuri学習ではバッチ埋め込みを使い、ブラウザで単発推論に切り替えると初期試行で296/300件しか一致しなかった。入力のバッチ条件を揃えて埋め込みを再生成し、全7方式を再実行した。しきい値や採用判断に独立セットの正解を使用していない。初回に失敗の調査・修正に使った手書きタスクは回帰用に移した。 [学習結果](../research/luxnora-v53/artifacts/metrics.json)

## 3階層の評価と採用判断

**A. モデル単体。** Ruri＋MLPは独立会話で最大237/300件（79.0%）。これは参照先だけの評価。否定の対象、任意の複数意図、機能集合、条件の構造化は専用ヘッドの出力範囲外。否定は独立のタスク評価で実測した。

**B. CoreとPlanner。** 同一の300会話を実行した最終参照先一致はVer.5.2の124/300からVer.5.3の243/300に改善した。明示的な開始ターンの成立も必要とする指標は70/300から169/300。全ターンの正解・目的達成を表す指標ではない。Ruri候補はシャドーで299/300件が有効な出力として通過し、252件で参照先が一致した。文字モデル候補は300件中243件が一致した。シャドーは候補を既存文脈と照合して実際のPlannerでコンパイルする。隔離側でRuri候補から173件の回答を生成し、52件に情報源、比較差分、または診断信号があった。今のアプリ回答、画面、承認、通信には反映しない。対象外の出力・読み込み失敗時も同じ回答に戻る。

独立の手書きタスクは7会話16ターン。通過はVer.5.2で7/16ターン・1/7会話、Ver.5.3で13/16ターン・4/7会話。学習にない読み取りと案内の組み合わせは1/3件。未同期件数を尋ねた際にカメラ異常を優先して件数が回答から抜けた例と、通過記録の出力を閲覧方法と誤った例が残った。否定評価は厳密採点で3/4件。残る1件は期待が確認保留だったが、実装は開場の否定以降を読み取りに解釈した。会話・独立タスクで許可外操作候補は0件。架空の数値生成の網羅的な評価は未実施。 [Core接続・回帰・失敗例](../research/luxnora-v53/artifacts/integration.json)

**C. ブラウザ。** Chromiumの隔離ページで、Worker内のRuri＋専用ヘッドと軽量MLPを動かした。双方ともPythonの予測と300/300件一致。Service Workerでキャッシュした後、通信を切って新規ページから同じ試験を行い、双方とも一致を確認した。このホストでのオンライン初回応答はRuri約4.13秒、軽量版約89 ms。既に埋め込みを取得した発話を反復したときのp95はRuri約3.0 ms、軽量版約1.1 ms。既存のRuri資産は約66 MB、今回のRuri専用ヘッドはブラウザ用JSONで約270 kB。推論を中断するとWorkerを終了し、次の要求で作り直せる。モデル資産は既存のRuriを再利用し、受付画面には読み込み経路を追加していない。本番の認証を伴うブラウザE2E、ブラウザプロセス自体を終了した後の再起動、iPad Safari、メモリ上限、長時間安定性は未検証。 [Chromium実測](../research/luxnora-v53/artifacts/chromium.json)

既存のVer.5.1回帰評価は開発8/8ターン、独立8/9ターン。独立の1件は従来から残る認識精度についての改善案の不足。Ruri候補の限定統合は見送った。最終参照先の改善は観測できた一方、複合依頼と途中の文脈、案内の精度に改善余地があり、シャドー候補の採用による目的達成率の向上は未実証。実用版のAutoとSwiftは従来の意味検索と決定論的処理を引き続き使う。自由な文章生成モデルの追加は未実施。

## 再現

Node.js 24、Python 3.12、NumPy 2.3.5、PyTorch 2.8.0 CPU、Chromiumを使用した。Ruriを新たに取得する工程にだけ外部通信が必要。

```sh
study=research/luxnora-v53
run=$(mktemp -d)
git worktree add --detach "$run/v52" 1d008ff
npm install
npm install --prefix "$run/browser" playwright-core
playwright="$run/browser/node_modules/playwright-core/index.mjs"
node "$study/prepare.mjs" "$run/data"
node scripts/prepare-luxnora-model.mjs "$run"
node "$study/ruri-features.mjs" "$playwright" /usr/bin/chromium "$run/luxnora-assets" "$run/data" "$run/data/ruri.json"
OPENBLAS_NUM_THREADS=1 python "$study/train.py" "$run/data" "$run/artifacts"
node "$study/evaluate.mjs" "$run/data" "$run/artifacts" "$run/v52"
node "$study/browser-probe.mjs" "$playwright" /usr/bin/chromium "$run/luxnora-assets" "$run/artifacts"
npm test
npm run test:rules
npm run build
```

回帰テスト271件、Firestoreエミュレーター9件、ビルドに合格した。

# Luxnora Ver.6.0 目的に基づく読み取り計画

基準は `luxnora/v5-3-context` の `2f05379`。変更は管理アプリのLuxnora、評価コード、研究成果物に限定した。受付・Apeir・Firestore規則・本番の変更はない。 [Ver.5.3評価](luxnora-v5-3-context.md)

## 実装

既存の言語理解が認識した依頼に、未同期記録の件数や年度比較の説明などの必須成果物を付ける。目的は開催区分・対象端末・期間・読み取り制約と結び付く。Plannerは成果物と許容される機能の対応を検査し、既存の型付きレジストリからDAGを構築する。同じ台帳や端末観測は計画内で共有する。条件付きの依頼では、前提が確認されたときにだけ専用の入力を取得する。複数出力の順序は依頼順を保持し、独立した成果物は続行する。 [言語と目的](../management-app/src/luxnora/language.ts) · [Planner](../management-app/src/luxnora/planner.ts)

未同期件数では、事実を返す提供元に入力型、出力型、コスト、必要な観測、検証方法を持たせた。要求した事実から逆向きに提供元を探索する。現在の件数が確認できなければ、同じ承認済み端末の過去報告に切り替え、その時点の件数と明記する。件数の欠損、範囲違い、未来の時刻、重複して承認済みとなった同一役割、負数は採用しない。数値が取れない場合は未確認と返す。現在報告・過去報告のどちらか一方を探す試験では逆向きの候補確認が1、前向きが2。両方が必要な場合は各方式2。探索計測はこの小さな台帳での候補数であり、一般の計画速度を示すものではない。探索深度4、提供元8、実行目標4件、通常の読み取り期限12秒。ネットワーク読み取りを並列に発行しない。 [事実の探索・検証](../management-app/src/luxnora/objective.ts)

年度比較の説明では、対象年度と実際の開場時間帯を照合し、整合した確定記録から差を計算する。「前年より多い／少ない」という前提が確認済みの差に反するときは、その検証結果を先に返す。比較に必要な前年記録や条件が揃わない場合は、整合した今年の台帳で依頼の範囲を集計して返す。確認できた同期・端末報告、原因候補、追加確認に必要な情報を区別し、因果関係を断定しない。既存の検証済み経験は同じ開催区分の有効なものだけ診断で使う。会話状態と操作承認は独立。処理中に開催区分や閲覧可否が変われば破棄し、以前の閲覧結果・承認は再利用しない。 [Core](../management-app/src/luxnora/core.ts) · [根拠と仮説](../management-app/src/luxnora/reasoning.ts)

## 学習と採用

Ver.5.3の軽量会話参照モデルを、実際のCoreを使う隔離シャドー評価に接続した。68件で候補を生成し、最終ターンの参照先を明示的に採点できた45件では45件が通過した。この評価の該当ケースで決定論的経路も成功していたため、応答経路への昇格は見送った。Ver.5.2の多タスクモデルには目的の検証や依存関係の構築に必要な出力がなく、以前の学習結果を参照し、実行に接続していない。Ver.5.3のRuri経路を調べ、今回の新しい目的探索でのRuri再学習・追加の端末検証は行っていない。 [シャドー評価](../research/luxnora-v6/artifacts/core.json)

別の実験では、現在報告・キャッシュ・欠損の優先順位を選ぶ小型MLPを3初期値で学習した。観測条件・候補・選択先・不適格条件を学習90、検証72、評価160件に分けた。採点ラベルは現行のデータ資格要件から作成し、人による品質ラベルは使用していない。全初期値で独立評価148/160件。単独では不適格な候補を12件選んだ。候補検証後は160/160件でルールと同じだったため、常用は見送った。 [順位付けの学習と重み](../research/luxnora-v6/artifacts/ranking.json)

## 同条件での比較

合成環境で本番・試験、欠損、不正な数値、古い報告、前年候補の重複、通信失敗、権限変更、取り消しを検証した。評価用の期待値は実行時にCoreへ渡さない。独立セットは単発104件と複数ターン104会話、各8種類の目的構造。各構造の条件を13通りのケースとして再利用した。独立した目的構造100件・会話構造100件の目標には届いていない。開発中に失敗や評価器の妥当性確認に使った270件は回帰用に分けた。 [独立ケース](../research/luxnora-v6/independent.mjs) · [回帰用の条件](../research/luxnora-v6/scenarios.mjs)

| 独立評価 | Ver.5.3 | Ver.6.0 |
| --- | ---: | ---: |
| ケースの最終成果物がすべて一致 | 80/208 | 184/208 |
| 会話の最終成果物がすべて一致 | 57/104 | 104/104 |
| 必須項目の充足 | 138/325 | 301/325 |
| 未同期件数を含む依頼の必須項目漏れ | 65/65 | 0/65 |
| 許可外の操作候補 | 0 | 0 |
| 過去記録の読み取り呼び出し | 73 | 65 |

会話指標は最後のターンの成果物を採点し、途中の全応答が正しいことは意味しない。必須項目には、情報不足時にその旨を明示することも含む。未同期件数の構造化出力を端末データと照合し、根拠なしの値は0件。すべての出力数値や回答の自然さを独立に評価したわけではない。複合依頼では、未同期件数に改善案を添える依頼を通常の集計と取り違えた例と、台帳の整合性確認がオフライン案内に埋もれた例が残った。一般化の結論は計測した目的構造に限定する。 [結果と失敗例](../research/luxnora-v6/artifacts/core.json)

## ブラウザと残課題

Chromiumの隔離ページで実際のCoreを起動し、単発の未同期照会と、前年取得に失敗する複合分析を各40回計測した。Service Workerでキャッシュした後に通信を切り、別ページで同一の回答が得られた。履歴取得は試験用の失敗応答であり、本番接続・認証・通信遅延は含まない。iPad Safari実機、実アプリでの認証付きE2E、自由文生成モデル、任意目的の汎用探索、500件以上への独立構造の拡張は未実施。 [Chromium計測](../research/luxnora-v6/artifacts/chromium.json)

## 再現

ルートから、Node.js 24、依存パッケージ、Python 3.12＋PyTorch 2.8 CPU、Playwright CoreとChromiumが利用可能な環境で実行する。

```sh
run=$(mktemp -d)
git worktree add --detach "$run/v53" 2f05379
node research/luxnora-v6/evaluate.mjs "$run/v53" "$run"
python research/luxnora-v6/rank.py "$run"
npm install --prefix "$run/browser" playwright-core
node research/luxnora-v6/browser.mjs "$run/browser/node_modules/playwright-core/index.mjs" /usr/bin/chromium
npm test
npm run test:rules
npm run build
```

既存の独立シナリオは8/9ターンで前回と同じ1件が未達。回帰テスト276件、Firestoreエミュレーター9件、ビルドに合格した。

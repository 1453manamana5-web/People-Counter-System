# Luxnora Ver.5.1 学習型知能の検証と運用支援

2026-11-28 JST。正式リポジトリの main は `ebb658b`、Ver.5.0は `6277ab0`。main に入っていないVer.5.0の変更を継承するため、そこから `luxnora/v5-1-learning` を作った。Apeir、旧QR-Ticket-System、Firestoreルールは変更していない。

## アプリに組み込んだ処理

- **目的と処理の組み合わせ**。計測ミスを減らす依頼を目的と捉え、現在の運営確認が必要かで候補となる計画を比較する。準備だけの依頼は現地の設置・試験ガイドを返す。当日の確認を含む場合は、既存Plannerが台帳と端末を診断した後、結果を使って案内を組み立てる。取得できない記録は不足と明示する。操作・取消・否定や年度比較を含む依頼は従来経路に渡し、独立したGuardを維持する。
- **会話から作業へ**。端末を確認した後の「最後に改善点をまとめて」は、有効な端末トピックが一つなら同じ方向を引き継ぐ。古くなった会話では方向を引き継がず、現在の開催区分を使う。確認し直した状況から助言を得る方式で、以前の回答を検証済みの診断結果として再利用する方式ではない。
- **確定した比較データの再利用**。権限確認済みの同じパネル内で、確定日・データの版・期間が一致する正常な前年集計だけを20秒間、最大4件保持する。取消、権限の未確認、開催区分切替に応じて破棄。最新・再取得の依頼は再読込する。ブラウザの長期ストレージや学習データには保存しない。
- **判定と制御**。Auto・Swiftの双方で上記の決定論的な処理を使う。比較の通信時間、再計画回数、変更候補のGuardはVer.5.0を継承。モデルによるFirestoreの書き込み、任意コードの実行、復旧の自動実行は追加していない。

## 学習データ、品質確認、モデル比較

`research/luxnora-hybrid/phrases.json` の67文と、Ver.5.0の学習用75文を使用した。別の22文でしきい値を調整し、その後に32文を採点した。既存の検証・独立データは学習に入れていない。ラベルを18項目の機能レジストリと照合し、NFKC正規化後の完全重複がないことを検証した。会話、状態、計画、操作の制約は `evaluation/v5-1` に別途保存。今回のモデルは単一の案内候補と保留の分類に限定した。学習に利用者の会話や学校の実データは使っていない。

768個のハッシュ化文字特徴を入力として、線形、32ユニットMLP、案内可否を補助タスクに加えたMLPをNumPyでCPU学習した。各方式は約0.08〜0.10秒の単発測定。入力層の重みをint8に量子化してから検証用データで採用しきい値を選んだ。MLPの出力層は浮動小数点。研究用の重み、失敗ラベル、再現コードを保存した。

| 同じ独立32文 | 一致 | 保留すべき文への案内 |
| --- | ---: | ---: |
| Ver.5.0の検索候補の先頭 | 13 | 5 |
| Ver.5.0の学習済み線形モデル | 14 | 2 |
| Ver.5.1の量子化線形 | 11 | 0 |
| Ver.5.1のMLP | 15 | 0 |
| Ver.5.1の補助タスク付きMLP | 16 | 0 |

検索候補の数字は生の検索順位の採点。アプリの案内可否やGuardを通過した結果とは区別する。補助タスクで1件改善したが、案内できる依頼のうち3件で別機能を提示し、半数が不一致だった。線形は誤案内を抑えた一方、保留が多くなった。採用基準に足りないため、どのモデルも製品の実行経路には接続していない。Ruriは既存の読み取り意図分類で、今回の機能IDの正答表を直接出力できないため上表に含めていない。

## 生成と回答の根拠

Ver.5.0と同じGGUF、同じCPU推論方式を使い、対応ラベルが共通する新しい13文にJSON Schemaを適用した。Ver.5.0の専用モデルは7/13、Qwen2.5-0.5Bは2/13、SmolLM2-135Mは0/13。生成モデルは保留すべき8文のうちそれぞれ6文、8文で機能を提示した。CPU2スレッドでのロードは約2.82秒、1.97秒、プロセス全体のピークRSSは約846 MiB、314 MiB。実機のメモリや速度とは区別する。モデルの出自・ライセンスとリビジョンはVer.5.0の報告書を参照。

確認済みの事実を短く言い換える別の4件では、数値と必須情報の簡易検査を通過したのはQwenが2件、SmolLM2が1件。検査は日本語の自然さ、語順、意味のすべてを保証するものではない。アプリの回答は検証済みデータと既存ガイドを組み合わせる経路を維持した。

## アプリ評価とブラウザ試験

| 評価 | Ver.5.0 | Ver.5.1 |
| --- | ---: | ---: |
| 開発用の目的達成 | 4 / 8 | 8 / 8 |
| 独立8シナリオのターン一致 | 4 / 9 | 8 / 9 |
| 独立評価での意図しない変更候補 | 0 | 0 |

固定した独立シナリオで選択された意図・端末方向、必要な根拠、変更候補の有無を実際のCoreに通して採点。残る1件は「認識精度を改善する準備」が開場準備の確認に分類され、改善案を組み立てなかった。独立セットで失敗したため、次の調整ではこのセットを最終評価として使い続けない。

試作線形モデルはChromiumで配布用のJSONとJavaScriptを使用した。ロード約31.5 ms、32判断のp95約2.3 ms。読み込み済みの同じページで通信を止めても出力が全一致した。Safari、iPad実機、オフラインでのページ再起動、ブラウザのメモリと長時間運用は未検証。Node CLIでも量子化後のPythonと32件の分類が一致した。

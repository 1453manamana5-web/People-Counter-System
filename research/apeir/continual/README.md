# Apeir α-09〜α-11 継続学習研究

研究基準は `apeir/alpha06-08` の `5bb3756`。調査時の正式mainは `ebb658b`、実用版の最新開発ブランチは `luxnora/v5-2-curriculum` の `1d008ff`。α-08の世界、診断GRU、状態予測GRU、ルール＋行動価値モデルを継承した。研究中の候補はローカルの仮想環境だけで利用する。 [α-08の報告](../causal/README.md)

## 仮想環境と分割

旧来の最大16ステップと、入口・出口・管理受信カウンターを使う96ステップの環境を比較した。長時間環境は開場直後、ピーク、閉場間際で通過発生率が変わる。端末別の認識負荷、長時間切断、未送信キュー、連鎖する複合障害、操作試行のクールダウンを含む。収集には障害を挿入しない正常対照も含めた。場内混雑は流量の変化で近似しており、来場者の軌跡や滞留位置はシミュレーションしていない。管理の計数反映と同期はα-08と同じ。Firestore、永続キュー、実機のカメラ認識・管理端末・試行時間の上限、実際のアプリ更新は別検証が必要。版は合成環境が変わったことを表す。

モデルに渡すのは観測可能な23信号を3時点分。潜在故障と同じ乱数での反実仮想は訓練ラベル・採点側だけで使用する。操作候補は観測から独立した既存の許可検査で制限し、実行直前にも仮想環境が再検査する。旧Worldの定数を拡張点に移して長時間環境で再利用した。旧環境3構成・90シードの1,346ステップは変更前と一致した。旧Worldのテストには、実アプリの `recoveryDecision` と共有条件を照合するテストが含まれる。 [旧Worldの実装](../causal/world.py) · [拡張World](day.py)

学習は旧条件2,338観測、追加の回線障害1,792観測。旧・新の検証は690・608観測、少数例はカメラ・負荷重複の新条件64観測。少数例の検証は448観測。モデル、閾値、操作マージン、優先学習分布は検証帯の乱数のみで決めた。最終評価は970000・980000・990000の各乱数帯を使い、固定診断では各環境27日分、閉ループでは各環境21日分。生成器を共有する合成範囲での外挿であり、完全に未知の実運用環境への外挿は未検証。 [学習データの内訳](artifacts/training.json)

## α-09 長期記憶

エピソードは版、観測履歴、故障、候補と確信度、行動、直後の結果、観測が得られた項目での予測誤差を保持する。記憶の正しさは合成環境の真値と比較する。重複は統合し、容量に達したら重大な事例、高誤差、比較的新しい事例を優先する。未検証、別バージョン、容量超過分を検索から外して保管し、再確認して復元できる。実際に4,130記録を作り、1,200件を索引に、2,930件を保管に回した。重大と判定した187件は索引または保管のいずれかに残した。非圧縮約4.34 MB、圧縮約697 kB。索引は距離計算時に真の原因を参照しない。

意味記憶として、診断・待機時の状態予測・行動別価値・直後の効果を共通GRUで学んだ。固定距離による事例検索、学習済みGRU単独、曖昧な観測だけ事例を混ぜる方式を分離して評価した。最も近い事例の原因集合は、旧短時間48/114、文化祭672/864、回線障害636/864で対象と一致した。異常の少ない環境では、正常同士で一致するケースを含む。学習器単独と比べ、事例併用は短時間で85→88件、回線障害で785→787件に改善した一方、文化祭は810→808件となり、異常の見逃しが37→41件に増えた。検索の常用は見送った。新しい版の記憶は保持していないため、旧版の記憶を混ぜず診断モデルへ戻した。 [記憶コード](memory.py) · [記憶・診断の詳細](artifacts/results.json)

## α-11 自己評価、学習選択、少数例

検証の故障群ごとに原因一致、判断の正誤、異常の見逃し、行動効果誤差を測り、弱点の比重で次のデータ収集候補を選ぶ。旧技能の復習は別の枠で残し、通常状態の観測も選択対象に含める。ランダム64件に対し、自動選択64件は複合障害を3件から6件へ増やした。通常学習、転移、能動的な事例選択、およびReptileの8外側更新を比較した。Reptileは旧短時間と回線障害で重みの初期値を更新し、別条件で64件の追加学習を行った。

## 独立評価

| 条件 | α-08 診断一致 | 今回の診断一致 | 今回の異常見逃し | 待機のみの復旧 | α-08の復旧 | 今回のルール＋価値の復旧 | 不要操作 α-08 → 今回 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧短時間 | 85/114 | 85/114 | 3/76 | 1/21 | 6/21 | 6/21 | 0 → 0 |
| 文化祭 | 771/864 | 810/864 | 37/151 | 17/23 | 27/27 | 27/27 | 12 → 12 |
| 回線障害 | 682/864 | 785/864 | 0/370 | 0/21 | 22/22 | 22/22 | 0 → 0 |
| カメラ・負荷 | 692/864 | 739/864 | 19/276 | 22/23 | 27/27 | 27/27 | 65 → 38 |

4条件すべてでルール＋価値はα-08と同数の復旧を維持した。未経験のカメラ・負荷条件では不要操作を65件から38件に減らし、文化祭では人への照会が18件から13件に減った。短時間の復旧6/21（28.6%）は目標の80%を下回り、短時間条件の診断85/114（74.6%）も85%に届かない。短時間の判断一致は209/231（90.5%）で、α-08の212/231を下回った。判断一致は訪問した状態での値で、同じ状態の指標はモデル別の `decision_exact` に保存した。すべての方式で許可外操作の実行は0件だった。

複合または保存異常と定義した重大条件では372観測中13観測を見逃した。弱点の順位は環境内の12組中12組で検証結果と同じ向きだった。単一の学習初期値での結果なので、学習自体の初期値に対する頑健性は未検証。CPUでのルール＋学習値の判断p95は0.31〜0.46 ms。検索対象のある条件での検索p95は0.27〜0.62 ms。評価用Pythonプロセス全体のピークRSSは約312 MiB。

行動価値単独は短時間の復旧が7件だった一方、計測漏れが58件で、ルール＋価値の30件を上回った。模倣で最良行動として学習した4,130件のうち、待機3,392件、再起動35件。短時間での模倣の復旧は4/21だった。過去の方策が操作を避けた理由の一つとして、このラベル分布があり得るが、当時のオンライン学習の原因をこの結果だけから断定できない。

即時効果のMAEは、効果ゼロ基準に対し、短時間で0.181→0.101、文化祭で0.101→0.072、回線障害で0.135→0.079。カメラ・負荷では0.096→0.103と悪化した。検証から求めた90%誤差幅の被覆はその条件で212/261（81.2%）。長期の状態予測も改善せず、回線障害の6ステップMAEはα-08の0.191に対し今回0.207だった。今後は現在状態の推定と行動の差分推定をそれぞれ検証してから用いる。 [予測・復旧の詳細](artifacts/results.json)


行動価値は同じ仮想状態から取りうる各行動を3ステップ先まで比較した差を学習する。模倣は同じデータから最大価値の行動だけを正解とする。待機、強化ルール、α-08ルール＋価値、今回のルール＋価値、価値単独、模倣を同じ初期シードで比較。状態予測は待機時の状態を再帰予測し、即時行動効果は同じ状態・同じ乱数で待機との差を別ヘッドから推定した。これらは仮想評価であり、オンライン強化学習の追加は0ステップ。以前のオンライン学習累計49,152ステップを維持する。

復旧成功率は観測された障害が発生してから安定状態に戻った割合。長時間環境では自然経過やシミュレーターによる障害終了でも復旧するため、操作の因果効果を示すために待機も測った。方式間で障害区間が合流・分離することがあり、検出された区間数は固定しない。旧短時間環境の復旧基準はα-08と同じ。本番環境への採用やデータ接続は行っていない。

## 再現

Python 3.12、PyTorch 2.8.0 CPU、NumPy 2.3.5。学習・採点ともローカルで実行できる。研究テスト10件と既存アプリの回帰テスト256件に合格した。保存した重みは各候補の最終エポックで、学習実行時にはエポックごとに最適化器、乱数、損失を含めて置換保存する。α-09を3エポックから8エポックへ再開する工程も実行した。

```sh
cd research/apeir/continual
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 PYTHONPATH=../causal
python -m unittest -v test_continual
python run.py --out /tmp/apeir-alpha09-11 --stage train
python run.py --out /tmp/apeir-alpha09-11 --stage eval
(cd artifacts && sha256sum -c SHA256SUMS)
(cd ../causal && python -m unittest -v test_world)
```

次の評価では、稼働中の正常対照と重大故障を固定した診断試験、障害が予定時刻に自動消失しない長時間の復旧試験、操作効果の検証を分ける。旧能力の保持が確認できた方式を研究候補にし、旧記憶の影響を版ごとに評価してから利用範囲を広げる。

# Apeir α-06〜α-08 因果・予測・計画研究

基準は研究ブランチ `apeir/alpha03-05` の `380246b`。実用版の最新開発ブランチ `luxnora/v5-1-learning` の `9c31d26` と正式 main の `ebb658b` を確認した。このブランチの変更は研究ディレクトリ内に限定する。保存済みのα-01〜α-05、受付・管理アプリ、Firestoreに変更はない。

## Apeir World

入口と出口を別々に持ち、各端末の通信、カメラ、認識、保存、負荷から、観測、端末内キュー、転送中の件数、管理アプリへの表示を計算する。故障と観測欠損、同期遅延、保存できなかった通過を区別する。複合障害・通信相関・持続障害を変えた標準、学内回線障害、混雑負荷の3構成を用意した。構成は同じ仮想環境内で条件を変更したもので、実機や別の独立実装ではない。各運用は最大16ステップ。

実アプリの復旧判定から、許可、表示中、追跡中の抑止、試行予算を抽象化した。共通条件の6ケースは実アプリの `recoveryDecision` をNodeで直接呼び出して照合した。同期は端末側の保存から転送・管理側表示へ進み、同じ転送中の件数は二重加算しない。実際のFirestoreトランザクション、永続キュー、カメラフレーム、端末の複数台ペアリング、時計補正、実時間の試行上限や長時間運転は再現していない。待機とプローブはどちらも次の通常観測を待つ。プローブは優先度の表現で、専用センサーや権限を追加しない。

候補行動は事前定義済みの9種。現在の観測による許可を先に確認し、仮想環境で実行直前にも同じ制約を検査する。予測値から新しい権限を得ることはできない。介入実験の `do(root=0)` は研究環境内の変数操作であり、計画の候補行動に含まれない。

## α-06 因果推論

機能間の向き付き依存関係は `artifacts/causal-graph.json`。同じ状態・同じ時刻の乱数を使って「そのまま」と「故障変数を一つ取り除く」を比較した。観測の差と計測漏れの差を記録し、効果が出ない場合も残す。複合障害では一つの原因を取り除いても、下流の症状が残る場合がある。1,971組の学習状態でベイズ診断の尤度を推定した。別に、通常観測のみを使うMLP・GRUを学習した。

| 同じ162状態 | 根本原因集合の完全一致 | 異常の見逃し / 144状態 |
| --- | ---: | ---: |
| 通常観測のルール | 40.74% | 6 |
| 通常観測のMLP | 38.27% | 11 |
| 通常観測のGRU | 39.51% | 9 |
| 介入結果付きベイズ | 61.73% | 7 |

ベイズ方式は介入結果という追加の証拠を入力できる上限寄りの比較。通常観測しか使えない方式と同じ情報条件ではない。原因別再現率、Brierスコア、変化を生じた介入数を保存した。別の正常対照108件では、GRUは46件を異常と判定した。ルールとビーム探索の復旧操作はどちらも0件。目標の原因診断85%・見逃し0件には届かず、介入に基づく診断を自律実行には接続していない。

## α-07 学習済みワールドモデル

3観測と指示行動から次の状態を予測するMLPとGRUを、5,276遷移で学習した。GRUは別の初期値のモデルも作り、推定の差を不確実性の指標にした。未来への予測は、モデル自身の予測を次の入力に戻す。予測中にシミュレーターを呼び出さず、採点側でのみ実際の仮想環境と照合する。

| 構成 | 現在値を固定した予測の6ステップMAE | GRUの6ステップMAE |
| --- | ---: | ---: |
| 標準 | 0.1758 | 0.1072 |
| 学内回線障害 | 0.3226 | 0.1290 |
| 混雑負荷 | 0.1910 | 0.1583 |

誤差は0〜1に正規化した状態の平均絶対誤差。1・3・6ステップ、MLP、GRUの結果と各分母を保存している。途中で終了した運用は長い予測の分母に含めない。単一ステップの90%誤差区間は検証用データで決め、独立データの各状態量に対する平均被覆率は90.28%。長期や状態の同時被覆率ではない。

同じ初期状態から「待機」と「操作」を分けて比べると、状態予測の差分は3構成すべてで効果ゼロの基準より誤差が大きかった。追加の1,676対で次状態差を直接学習したが、別の独立データでも改善しなかった。標準構成ではMAEが効果ゼロ0.0228、GRU差分0.0309、直接学習0.0719。次状態予測の成績だけで操作の効果を判断しない。

## α-08 行動計画と旧方式の比較

GRUの根本原因候補、状態予測のアンサンブル、仮想環境の3ステップ評価で学習した行動の優先順位を使い、深さ3・幅4のビーム探索と候補サンプリングを比較した。管理された範囲の行動のみを展開し、実行後は次の観測で計画を立て直す。安全に実行できる候補がなければモデルを起動せず、待機・観測または人への確認へ切り替える。

| 同じ初期シードの復旧試行162件 | 復旧 | 復旧操作のうち再起動 | 不要な操作 | 判断p95 |
| --- | ---: | ---: | ---: | ---: |
| 強化ルール | 35 | 121 | 33 | 0.03 ms |
| α-03 GRU | 14 | 38 | 4 | 1.80 ms |
| α-04 DQN | 1 | 0 | 0 | 1.28 ms |
| α-05 | 14 | 114 | 33 | 1.11 ms |
| α-08 ビーム探索 | 10 | 2 | 0 | 3.17 ms |
| α-08 候補サンプリング | 10 | 2 | 0 | 4.12 ms |

旧モデルには入口・出口の観測列を別々に入力し、旧来の待機・同期・カメラ・認識・照会を新しいIDに写像した。旧モデルに新しい負荷原因の出力はない。復旧率は同じ初期シードから各方式が自ら行動した結果。判断正解は3ステップの仮想評価に対する一致で、共通観測列での一致率と、各方式が実際に訪れた状態での一致率を別々に保存した。共通の2,120判断では強化ルール50.24%、α-05が59.06%、ビーム探索57.55%、ルール＋学習値50.52%だった。共通状態での一致が高くても、復旧に至るとは限らない。CPUプロセス全体のピークRSSは約318 MiB。速度・メモリはこの仮想実験の値。

予測差の弱さを受け、同じ状態から安全な行動をそれぞれ仮想実行し、3ステップの評価値と待機との差を学ぶ回帰モデルも作った。これは介入に基づくオフラインの行動価値学習。実機学習や追加のオンラインRLではない。ルールを土台に、複数操作が可能で学習値と予測が支持する場合にだけ順序を変える構成を比較した。差のしきい値は検証用データで決め、初回評価とは別の独立162件を使用した。

| 追加の独立162件 | 復旧 | 複合障害の復旧 / 125件 | 不要操作 | 人への照会 |
| --- | ---: | ---: | ---: | ---: |
| 強化ルール | 26 | 13 | 24 | 30 |
| ビーム探索 | 8 | 3 | 0 | 29 |
| 学習値だけで選択 | 20 | 10 | 5 | 94 |
| ルール＋学習値 | 26 | 13 | 18 | 30 |

最後の構成は復旧件数を維持しながら不要操作を6件減らした。複数操作の後に復旧したのは、強化ルール22件、ルール＋学習値21件。すべての方式・評価で仮想環境が拒否する権限外操作の実行は0件だった。復旧率80%の目標には届いていない。

### α-04が操作を避けた理由の切り分け

旧環境で保存済みPPO・DQNを再生した。学習に近い条件340判断では50判断、未知条件469判断では45判断で、許可された復旧操作が存在した。マスク後も両モデルとも選択は0件。旧DQNのマスク前の許可外候補は学習に近い条件で2件、旧PPOは0件だった。許可制限と分布変化だけで結果を説明できない。

同じ状態から照会と復旧操作を比較すると、照会が許可済みの復旧操作のいずれより有利だったのは、即時報酬では0件、3ステップ報酬では4件と2件。照会の終了効果は一部にはあるが、全件の説明にはならない。新しい模倣学習でも3,144判断のうち、最良ラベルは待機2,039、照会799、能動操作306件で、単純な最良ラベル学習は操作を避けた。追加方式では最良ラベルだけを当てず、許可された行動ごとの価値差を学び、差が大きい事例を重くした。追加のオンライン強化学習は実施していないため、以前の49,152ステップに今回の遷移数を足していない。100万ステップは未達。

## 再現手順と研究としての扱い

Python 3.12、CPU版PyTorch 2.8、NumPy 2.3.5。旧世代比較には既存 `evolution/requirements.txt` のGymnasium・Stable-Baselines3も必要。

```sh
cd research/apeir/causal
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
python train.py
python effect_model.py --epochs 6 --train-only
python effect_model.py --epochs 12 --resume
python evaluate.py
python compare_values.py
python common_decisions.py
python controls.py
python inspect_rl.py
python -m unittest -v test_world
(cd artifacts && sha256sum -c SHA256SUMS)
```

各学習のエポックごとに重み、最適化器、乱数状態、損失履歴を保存する。直接効果モデルは6エポックから12エポックへの再開を実行した。再開エポック数と評価シードは先に固定し、最終スコアを見て更新していない。学習・検証・最終評価は乱数帯を分離し、最終評価は各構成3シード群で実施した。

強化ルールを比較基準として維持し、ルール＋学習値だけを追加調査候補に残す。ビーム探索と直接効果モデルは研究結果として保管。別方式のGNN・Transformer・状態空間モデル、MCTS、オンラインRLの再学習、長時間・複数教室の実機評価は未実施。研究テスト7件と既存アプリの回帰テスト256件が通過した。端末・管理環境への接続や本番反映も行っていない。

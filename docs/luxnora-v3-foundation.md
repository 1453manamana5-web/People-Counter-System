## 今回の設計と実装

- 管理画面は `runtime.ts` を通して解釈、候補検証、重複除去、回答、文脈更新を順に行う。回答は同じイベント・運用区分で取得されたスナップショットを参照する。イベント・区分の切替で会話を破棄し、単一の読み取り対象のみ5分間引き継ぐ。
- Auto は短文が解決できなかった場合に Ruri を利用し、Swift はローカルの軽量処理のみで応答する。Ruri は読み取りの許可リストを通し、時間・対象・操作条件を落とす可能性がある文はフォールバックの対象外とする。
- 開場・閉場・予定変更は定型の明示指示1件だけを候補にする。既存のイベント管理画面で確認してから実行する。候補と見守りの申し出は新しい依頼で失効する。解析途中の取り消しは要求番号を更新し、完了した旧応答を無視する。起動済み Worker 内の計算や Firebase SDK の通信自体を中断する機能は今後の対象。
- 滞在人数の増減は既定で15分差を表示する。同期・整合性・開場時間を検証してから計算する。「閉場まで」の予測は、選択中の開催日の閉場時刻と一致する点だけを採用する。取得不能時は不足条件を表示する。前年の照会では、同じイベント系列に前年度の確定日が1件だけある場合に本番台帳を読み、指定の時間帯の入退場回数も回答する。複数候補、相対時間、滞在人数の比較は既存画面に案内する。
- 意図ごとの既存集計を再使用し、変更操作に Firestore の直接呼び出しを増やさない。受付アプリの本番認識経路は基準値測定のため保持した。

## 評価

- 既存の言語・会話・計測テストを回帰評価に使用し、新規の実行経路テストは自動 CI に含めた。追加の評価セットは解釈結果の意図、時間帯、役割、操作候補、取り消しを採点する。公開済みの固定セットは次回から回帰用とし、性能の最終判定では別の未見セットを用意する。
- 小規模評価の比較は `npm run evaluate:luxnora -- /path/to/baseline-checkout`。基準版のローカル判定は21ターン中16件、14会話中9件が一致。V3 Swift は21件、14会話が一致。意図しない操作候補は2件から0件。操作の確定は試験対象外。言語理解98%の目標達成を判定できる標本規模ではない。
- 基準版は通常テスト239/240、ビルド失敗。V3 は通常テスト247/247、ビルド成功、ローカル Firestore エミュレーター9/9。基準版のエミュレーターテストは未実施。
- Chromium でビルド済み Ruri Worker と同梱資産を実際に実行した。初回の読み込み込み9.9秒、読み込み後90 ms、対象外入力の保留53 ms。ネットワークを無効化した同一セッションでは88 msで分類した。配布用資産の合計は約64 MiB。LAN上の単発測定で、Safari の速度・メモリ・初回オフライン起動を示す値ではない。
- 受付の回帰テストは合成検出、重なり、方向、台帳、再同期を検証する。カメラ画像の認識精度、学校 Wi-Fi、8時間連続計測は未測定。

## Apeir α-01

`research/apeir/train.py` で再学習できる。次のコマンドは合成テレメトリを生成し、教師あり学習済み重みと評価結果を出力する。

```sh
python3 -m venv .venv
.venv/bin/pip install -r research/apeir/requirements.txt
OPENBLAS_NUM_THREADS=1 .venv/bin/python research/apeir/train.py --output /tmp/apeir-alpha-01
```

訓練10,000件、閾値選定1,500件、評価2,000件。データセットごとに異なる乱数種と欠損・誤報率を使用した。線形 softmax の正答率は55.8%、ルール方式は39.2%。異常を観察継続と判定した件数は119対17で悪化した。今回の出力は診断候補の分類に限定し、復旧の自動選択や実行には接続しない。合成データの生成モデルに対する精度であり、学校の運用環境での精度は不明。

## 残る工程

1. 学校の iPad でカメラの実計測、初回と再開の時間、ネットワーク遮断、長時間稼働を測る。個人を識別しない合計の手動正解を使い、逆方向、同時通過、遮蔽、漏れを個別に集計する。
2. 前年の照会を認証済みの環境で検証し、対応する日が複数ある場合の選択と、比較可能な条件を確認したうえでの差分集計を実装する。複数作業の依存関係、優先度、永続化した再開、長期・経験記憶は実装が残る。
3. 未見の言語と運用シナリオを追加する。Apeir は誤った正常判定を抑える判定基準と未見の障害パターンで再評価する。
4. 実機の結果が得られた段階で Ruri 継続と受付の検出方式を比較し、本番統合を判断する。

# Luxnora Ver.4.1 日本語理解

2026-11-28 JST。作業開始時の main は `ebb658b`、基準は `luxnora/v4-integration` の `34a71a1`。main にVer.4.0のコミットが入っていないためVer.4.0を起点とした。Apeirおよび旧QR-Ticket-Systemへの変更はない。

## 実装と失敗分析

Ver.4.0では、`language.ts` の条件抽出と文字n-gram、`semantic.ts` のRuriフォールバック、`context.ts` の文脈補正が主な解釈経路だった。意図ラベルに条件を関連付けられず、複数の文に分かれた依頼を保留したり、直前の指標を訂正する代わりにイベント画面へ誘導したりすることがあった。Ruriは短い未解決文の意図分類であり、範囲・否定・条件を生成しない。

- **語句と意味表現**。表記と口語の揺れを整え、既存の時間帯・対象・指標抽出を再利用する。複数の要求を、目標の配列、判断の依存関係、閲覧のみの制約として表現する。読み取りの前提をすべて解決できない複合文は保留する。重要操作の解析と確認は既存のGuardを経由する。
- **条件と実行**。CoreからPlannerに型付きの依存を渡す。「少なければ」は前年との確定記録差が負の場合、「異常が見つかったら」は選択した端末の新しい状態報告に異常がある場合にだけ原因候補を整理する。条件を検証できない場合は保留する。前年の数字と現在の診断に因果関係があるとは判定しない。確認できる診断範囲が開催日全体の場合はその範囲を明示する。
- **文脈**。直近と一つ前の読み取り条件を保持し、前年との比較を維持したまま午後に変更したり、指標を入場から退場へ切り替えたりできる。既存の端末・比較の個別の話題も保持する。「人数が減った」は期間指定なしの滞在人数が直前の話題なら滞在の変化を確認し、比較の対象が決まらなければ質問を返す。文脈の5分制限とイベント・端末・運用区分による既存の分離を継承する。
- **実行方式**。決定できる条件と短文を端末内で処理し、Autoでは未解決の短い読み取り依頼だけRuriに渡す。SwiftはWorkerを起動しない。両方式で同じGuardとデータ検証を使う。「それはせんといて」などの取り消しは、パネルから待機中・実行中の処理にも即時適用する。

## 言語と計画の検証

`npm run evaluate:luxnora:v41 -- /path/to/v4-checkout` で開発セット、末尾に `--independent` を加えて独立セットを測る。開発用セットは実装前に作成し、失敗を修正するため使用した。独立セットは別の文章・会話で実行し、採点結果は実装調整に使用していない。

| 測定 | Ver.4.0 | Ver.4.1 |
| --- | ---: | ---: |
| 開発16ターンの完全一致 | 8 | 16 |
| 独立24ターンの完全一致 | 14 | 24 |
| 独立10シナリオの全ターン一致 | 2 | 10 |
| 独立24ターンで意味モデルに照会した回数 | 6 | 1 |
| 独立24ターンの意図しない操作候補 | 0 | 0 |

完全一致には意図の順序、端末、期間、比較指標、指定シナリオでの制約・依存・取り消しを含める。各分野の失敗例と所要時間は `evaluation/v4-1` に保存。評価はNode上で意味モデルを未解決とするスタブを用いたため、モデル照会回数は実際の利用頻度と区別する。実行結果は別の自動試験で検証した。前年同期の確定差が負の場合、ゼロの場合、未確定の場合と、端末観測が新しい場合と古い場合を実際のCoreとPlannerに通した。

## 専用モデルとRuri

`research/japanese-intent` の合成データを用いて、文字1〜3-gramを入力とする線形モデルと24ユニットの小規模MLPをCPUで学習した。学習54文、しきい値調整18文、独立20文。文章は分割ごとに別の表現群を作成し、利用者の会話は使用していない。再学習は `OPENBLAS_NUM_THREADS=1 python3 research/japanese-intent/train.py`。学習済みの重みは `weights.npz`。試作モデルは読み取り意図または保留を分類し、条件や操作は出力しない。

| 同じ独立20文 | 一致数 | 保留すべき文を読み取りと誤認 |
| --- | ---: | ---: |
| 線形モデル | 11 | 1 |
| MLP | 10 | 1 |
| Ruri v3 30M | 6 | 0 |

Ruriはこの難しい20文を全件保留した。試作モデルは一部の未知表現を分類したが、対象外の誤認が各1件あり、アプリへ統合していない。Ruriは同じ量子化済み重みとしきい値で、参照文を長さ順に並べて最大12文ずつまとめて前処理する。Chromiumで同じローカル資産を使った初回分類は、各1回の計測で8.17秒から6.76秒に短縮した。約64 MiBの配布資産は同一。オフライン再起動、メモリ使用量、iPadの処理時間は未測定。
